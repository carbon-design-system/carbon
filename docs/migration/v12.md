# v12

This document describes the current consumer impact of moving an application
from Carbon Design System v11 to v12, organized by package. It assumes the v12
release behavior is already enabled in your project. See the
[feature flag documentation](../feature-flags.md) for the source of truth on
flag names, package availability, and associated codemods.

Use the package sections below to identify application code, behavior, visual
tests, and custom styles to review when moving to v12. Each section presents the
current v12 behavior and its consumer impact rather than implementation history.

- [`@carbon/utilities`](#carbonutilities)
- [`@carbon/react`](#carbonreact)
- [`@carbon/styles`](#carbonstyles)
- [`@carbon/web-components`](#carbonweb-components)

## `@carbon/utilities`

### Utilities Temporal polyfill

The date picker primitives in `@carbon/utilities/date-picker` are built on the
Temporal API, which is not yet universally available: no version of Safari
implements it, and Chrome and Edge only gained it in 144.

Importing `@carbon/utilities/date-picker` now installs
[`temporal-polyfill`](https://github.com/fullcalendar/temporal-polyfill) (~20 kB
gzipped) on `globalThis`, and only when the engine does not already provide
`Temporal`, so a native implementation is always preferred. Nothing is required
in application code. Do not add a second Temporal polyfill, as two
implementations competing for the same global is a source of hard-to-diagnose
errors.

This reaches consumers through the preview v12 date picker in
[`@carbon/react`](#carbonreact) and
[`@carbon/web-components`](#carbonweb-components). Review bundle-size budgets
and any Temporal polyfill your application already installs, which is now
redundant.

## `@carbon/react`

### React tile default icons

`ClickableTile` now supplies an `ArrowRight` icon when no `renderIcon` is
provided. A disabled clickable tile uses the `Error` icon, replacing any
consumer-provided icon. The component API and interaction model do not otherwise
change.

Review layouts, snapshots, and tests that assume a clickable tile has no
trailing icon or that a disabled tile preserves a custom icon.

### React AI label and decorator placement

Interactive decorators, including `AILabel`, are rendered outside native `label`
and `legend` elements and outside sortable table header buttons. `ClickableTile`
with an element decorator wraps the link and decorator in an outer wrapper so
the decorator is not inside the link.

Label-like props such as `labelText`, `titleText`, `legendText`, and `label`
must not include interactive content. Move help triggers, toggletips, and other
interactive controls to a sibling element or to the component's `decorator` prop
when one is available.

Review DOM selectors, snapshots, and tests that assume decorators are nested
inside labels, legends, sortable header buttons, or clickable tile links.

### React tile radio icons

`RadioTile` uses `RadioButton` and `RadioButtonChecked` icons instead of
`CheckmarkFilled`. The selection indicator is present in both selected and
unselected states, with its layout controlled by the related
[Sass tile radio icon change](#sass-tile-radio-icons).

The React component API does not change. Review custom icon assumptions, visual
snapshots, and layouts that previously expected an indicator only in the
selected state.

### React OverflowMenu composition

`OverflowMenu` now uses the `Menu`-based implementation. Its item composition
changes from `OverflowMenuItem` children to `MenuItem` and `MenuItemDivider`:

```diff
- <OverflowMenu aria-label="Actions">
-   <OverflowMenuItem itemText="Edit" />
-   <OverflowMenuItem hasDivider isDelete itemText="Delete" />
+ <OverflowMenu label="Actions">
+   <MenuItem label="Edit" />
+   <MenuItemDivider />
+   <MenuItem kind="danger" label="Delete" />
  </OverflowMenu>
```

Item text moves from `itemText` to `label`, delete items use `kind="danger"`,
and dividers are separate `MenuItemDivider` components. Item props such as
`href`, `disabled`, `className`, and `onClick` remain available;
`wrapperClassName` is folded into `className`.

The menu is placed `$spacing-02` (4px) from the trigger.

Review parent labels, item customizations, wrapper classes, and tests or
selectors that depend on the previous child structure.

### React MenuButton and ComboButton

There is no React component API change. The menu is placed `$spacing-02` (4px)
from the trigger, matching OverflowMenu.

Review visual snapshots and layouts that previously expected the menu flush
against the trigger.

### React Button radius

There is no React component API change. Buttons inherit radius from CSS custom
properties defined in `@carbon/styles`. See the
[Sass Button radius change](#sass-button-radius).

### React StructuredList selection

Selectable `StructuredListRow` components now use the `selection` prop and
automatically render a radio-button indicator in the first cell. Consumer-added
`CheckmarkFilled` cells are no longer part of the selection pattern. The
indicator's visual treatment is controlled by the related
[Sass structured-list change](#sass-structured-list-selection-icons).

Review selectable rows, custom selection cells, cell-position assumptions, and
visual snapshots.

### React dynamic floating styles

Floating surfaces use Floating UI's fixed-position styles even when `autoAlign`
is `false`. This does not add collision detection; `autoAlign` continues to
provide dynamic positioning and collision detection together.

The v12 list-box menu gap is applied through Floating UI when a ComboBox,
Dropdown, or MultiSelect menu is floating, so flipped menus stay clear of the
field. See the [Sass list-box menu change](#sass-list-box-menus).

The change affects `ComboBox`, `Dropdown`, `MultiSelect`, `MenuButton`,
`ComboButton`, `OverflowMenu`, and `Popover`, including Popover-based `Tooltip`
and `Toggletip` surfaces. Review overlays inside scrolling, transformed, and
clipping containers, along with code that depends on the previous positioning
context.

### React Toggle label spacing

There is no React component API change. React receives the reduced spacing
between a Toggle's label text and control through its `@carbon/styles`
re-export. See the
[Sass Toggle label spacing change](#sass-toggle-label-spacing) and review visual
snapshots or application overrides that depend on the previous spacing.

### React Tag border radius

There is no React component API change. React Tag, including dismissible,
selectable, operational, and skeleton variants, receives size-based corner radii
through its `@carbon/styles` re-export. See the
[Sass Tag border radius change](#sass-tag-border-radius) and review visual
snapshots or application overrides that depend on the previous pill shape.

### React Pagination preview APIs

`unstable_Pagination` / `preview_Pagination` and `unstable_PageSelector` /
`preview_PageSelector` are removed. Use the stable `Pagination` component.

The default page-select control is built in. Omit `pageSizes` to hide the items
per page selector. Use `renderPageSelect` when you need a custom page-select
control in place of the previous `PageSelector` child.

```diff
- import {
-   unstable_Pagination as Pagination,
-   unstable_PageSelector as PageSelector,
- } from '@carbon/react';
-
- <Pagination pageSizes={[10, 20, 30]} totalItems={100}>
-   {({ currentPage, onSetPage, totalPages }) => (
-     <PageSelector
-       currentPage={currentPage}
-       onChange={(event) => onSetPage(event.target.value)}
-       totalPages={totalPages}
-     />
-   )}
- </Pagination>
+ import { Pagination } from '@carbon/react';
+
+ <Pagination pageSizes={[10, 20, 30]} totalItems={100} />
```

Review imports, child render-prop usage, and tests or selectors that target
`.cds--unstable-pagination`.

## `@carbon/styles`

### Sass Menu border radius

The corners of the menu and menu-items are now rounded via the border-radius
tokens `$border-radius-08` and `$border-radius-04`, respectively. There is a
`$spacing-02` padding within all sides of the menu, and small adjustments were
made to submenu positioning and focus states (for danger menu-item) to
accommodate for the new styles.

### Sass list-box menus

List-box menus used by ComboBox, Dropdown, and MultiSelect now have rounded
corners, inner padding, a border, and a `$spacing-02` gap from the field. Upward
menus apply that gap below the menu. Auto-aligned or dynamically positioned
menus keep the same gap; it is not applied as CSS margin on the floating node.

This style change supports both
[`@carbon/react`](#react-dynamic-floating-styles) and `@carbon/web-components`.
Review visual snapshots, custom list-box menu offsets, and overlays that assumed
the menu was flush with the field.

### Sass Button radius

Buttons read radius from CSS custom properties instead of a fixed
`$button-border-radius` of `0`. The default fallback is `$border-radius-max`
(fully rounded). Per-corner properties override the base when set:

- `--cds-button-radius`
- `--cds-button-radius-ss`
- `--cds-button-radius-se`
- `--cds-button-radius-es`
- `--cds-button-radius-ee`

Carbon sets these on containing components so buttons match their context.
`$button-border-radius` is no longer the v12 visual default.

| Context                               | Token                     |
| ------------------------------------- | ------------------------- |
| Default button                        | `$border-radius-max`      |
| Data table toolbar                    | `$border-radius-00`       |
| Pagination                            | `$border-radius-00`       |
| Pagination nav                        | `$border-radius-00`       |
| Modal footer                          | `$border-radius-00`       |
| Modal close                           | `$border-radius-00`       |
| Dialog footer                         | `$border-radius-00`       |
| Dialog close                          | `$border-radius-00`       |
| Button set                            | `$border-radius-00`       |
| Action set                            | `$border-radius-00`       |
| Breadcrumb overflow menu              | `$border-radius-00`       |
| Side panel                            | `$border-radius-00`       |
| Code snippet                          | `$border-radius-00`       |
| Coachmark                             | `$border-radius-00`       |
| Edit in place                         | `$border-radius-00`       |
| Header                                | `$border-radius-00`       |
| Actionable notification               | `$border-radius-00`       |
| Card                                  | `$border-radius-00`       |
| Contained list                        | `$border-radius-00`       |
| Combo button (joined sides)           | `$border-radius-00`       |
| Combo button (outer corners)          | `$border-radius-max`      |
| AI Label footer actions               | `$border-radius-00`       |
| AI Label last footer action (end-end) | `$border-radius-08 - 1px` |

Set the same properties on your own containers to opt a region into a different
radius:

```css
.my-toolbar {
  --cds-button-radius: 0;
}
```

This style change supports both [`@carbon/react`](#carbonreact) and
[`@carbon/web-components`](#carbonweb-components). Review visual snapshots,
`$button-border-radius` Sass overrides, and hardcoded `border-radius` rules on
`.cds--btn`.

### Sass tile radio icons

Radio-tile selection icons are always visible instead of appearing only for the
selected state. The layout also reserves additional inline-end space for the
icon and for AI labels or decorators.

This style change supports both the
[React tile behavior](#react-tile-radio-icons) and the
[Web Components tile behavior](#web-components-tile-radio-icons). Review custom
tile padding, icon visibility overrides, and snapshots for both packages.

### Sass structured-list selection icons

Structured-list selection icons are no longer filled transparently while
unselected, and checked icons use the primary icon color. The legacy last-cell
width and padding override is no longer applied. This style change accompanies
the [React StructuredList behavior](#react-structuredlist-selection).

Review custom last-cell sizing, selection icon colors, and styles that assumed
the selection indicator occupied the final cell.

### Sass Toggle label spacing

The block-end margin between a Toggle's label text and control changes from
`$spacing-05` to `$spacing-03`.

This style change supports the [React Toggle](#react-toggle-label-spacing) and
the [Web Components Toggle](#web-components-toggle-label-spacing). Review visual
snapshots and custom spacing overrides in both packages.

### Sass Tag border radius

Tag corners are no longer pill-shaped. Small tags use `$border-radius-02`.
Medium and large tags use `$border-radius-04`. Dismissible close buttons and
their focus indicators use the same radius as the parent tag. Skeleton tags
follow the same size-based radius.

This style change supports both the [React Tag](#react-tag-border-radius) and
the [Web Components Tag](#web-components-tag-border-radius). Review custom Tag
radius overrides and visual snapshots in both packages.

## `@carbon/web-components`

### Web Components tile default icons

`cds-clickable-tile` renders `ArrowRight` when it has no custom icon, or `Error`
instead when that tile is disabled. Its interaction model does not otherwise
change.

Review layouts and visual tests that assume there is no trailing icon or that a
disabled tile preserves a custom icon.

### Web Components tile radio icons

`cds-radio-tile` uses empty and checked radio-button icons instead of
`CheckmarkFilled`. The icon remains visible in both states and the component
reserves space for it through the related
[Sass tile radio icon change](#sass-tile-radio-icons).

Review custom icon assumptions, tile padding, and visual snapshots that expect
an indicator only in the selected state.

### Web Components OverflowMenu composition

`cds-overflow-menu` now expects a direct `cds-menu` child using the same
composition model as menu button and combo button. The deprecated
`cds-overflow-menu-body` and overflow-menu-item composition is replaced by menu
items and dividers:

```html
<cds-overflow-menu label="Actions">
  <cds-menu>
    <cds-menu-item label="Edit"></cds-menu-item>
    <cds-menu-item-divider></cds-menu-item-divider>
    <cds-menu-item kind="danger" label="Delete"></cds-menu-item>
  </cds-menu>
</cds-overflow-menu>
```

The menu is placed `$spacing-02` (4px) from the trigger.

Review child composition, menu labels, item customizations, and tests or
selectors that depend on the deprecated elements.

### Web Components MenuButton and ComboButton

There is no Web Components attribute or API change. `cds-menu-button` and
`cds-combo-button` place the menu `$spacing-02` (4px) from the trigger, matching
OverflowMenu.

Review visual snapshots and layouts that previously expected the menu flush
against the trigger.

### Web Components Button radius

There is no Web Components attribute or API change. `cds-button` inherits radius
from CSS custom properties through the shadow boundary. See the
[Sass Button radius change](#sass-button-radius).

### Web Components dynamic floating styles

For Web Components, this positioning change applies to `cds-overflow-menu`.
Floating UI applies dynamic fixed-position styles without collision detection
when `autoalign` is `false`. When `autoalign` is `true`, collision detection is
included.

Review menus inside scrolling, transformed, and clipping containers, along with
code that depends on the previous positioning context.

### Web Components Toggle label spacing

`cds-toggle` reduces the block-end spacing between its label text and control.
This mirrors the [Sass Toggle change](#sass-toggle-label-spacing). Review visual
snapshots and custom spacing overrides.

### Web Components Tag border radius

There is no Web Components API change. `cds-tag`, `cds-dismissible-tag`,
`cds-selectable-tag`, `cds-operational-tag`, and `cds-tag-skeleton` receive
size-based corner radii through the related
[Sass Tag border radius change](#sass-tag-border-radius). Review visual
snapshots and custom radius overrides.
