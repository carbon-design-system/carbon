# Form participation

Form components participate in a `<form>` natively, through
[`ElementInternals`](https://developer.mozilla.org/en-US/docs/Web/API/ElementInternals),
instead of the deprecated `formdata` event. The browser treats them as real form
controls.

## The API

Import the component barrel and use the canonical tag:

```js
import '@carbon/web-components/es/components/text-input/index.js';
```

```html
<cds-text-input name="email"></cds-text-input>
```

Child elements stay as they are, so a `cds-select` still holds `cds-select-item`
children.

Date picker is the exception. Import `date-picker/next` and use
`<cds-preview-date-picker>` until that rewrite replaces the canonical tag.

### What the port deletes

The v2 story validates by hand before submitting, because `required` lives on
the host while the real `<input>` is in shadow DOM:

```diff
- const hasInvalidRequired = Array.from(
-   document.querySelectorAll('[required]')
- ).some((el) => {
-   const input = el.shadowRoot?.querySelector('input');
-   return input ? !input.reportValidity() : false;
- });
- if (hasInvalidRequired) return;
  form.requestSubmit();
```

`requestSubmit()` runs constraint validation itself once the controls are real
form controls, so the loop goes away. The Password field carries both `required`
and a `pattern`, and both are enforced — submit with a weak password and the
browser blocks it and fires a native `invalid` event, which you can watch in the
**Actions** tab.

Values reach the form the same way: no `formdata` listener, no manual
collection. Submit and the entries appear below the form.

### Still on preview tags

`cds-date-picker` still uses the v2 `formdata` path. Form association for that
component lives on `<cds-preview-date-picker>` (the Temporal rewrite) until it
replaces the canonical tag. `cds-file-uploader` is not form-associated.

## `cds-button` cannot submit these forms

The examples use native `<button type="submit">` rather than `cds-button`.
`cds-button` renders its `<button>` inside shadow DOM and is not
form-associated, so it cannot reach the surrounding `<form>` — clicking it
submits nothing. Form participation on the inputs does not help with this; the
button needs the same treatment.

## Notes

- `disabled` reports only the element's **own** attribute, matching
  `HTMLInputElement.disabled`. An element inside a disabled `<fieldset>` reports
  `false` and matches `:disabled` instead.
- `cds-multi-select` keeps the v2 joined wire format (`name=a,b`) rather than
  one entry per selection.
- Each control also exposes the standard `form`, `labels`, `validity`,
  `validationMessage`, `willValidate`, `checkValidity()` and `reportValidity()`
  surface.

For the full picture, see the
[v3 migration guide](https://github.com/carbon-design-system/carbon/blob/main/docs/guides/cwc-v3-migration.md#form-participation-moves-to-elementinternals).
