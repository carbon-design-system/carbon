# Migrating from `carbon-components-angular`

> Already on `@carbon/angular`? Jump to the
> **[Component stories](?path=/docs/components-button--docs)** or run the
> codemods below.

---

## Two-step migration path

`@carbon/angular` is designed to make migration low-friction by providing a
dedicated `@carbon/angular/legacy` entry point that matches the
`carbon-components-angular` API. You don't have to modernize everything at once.

### Step 1 — Drop-in import swap (no template changes)

Install `@carbon/angular` and swap import paths to `@carbon/angular/legacy`.
Your selectors (`cds-*`), templates, and most `@Input()` / `@Output()` bindings
stay exactly as they are.

```bash
npm install @carbon/angular @carbon/web-components
npm uninstall carbon-components-angular
```

```ts
// Before
import { ButtonModule } from 'carbon-components-angular';

// After — legacy entry point, no template changes required
import { ButtonComponent } from '@carbon/angular/legacy';
```

Run the report codemod first to see what needs changing, then the write codemod
to handle import paths automatically:

```bash
npx @carbon/upgrade migrate cca-report-imports
npx @carbon/upgrade migrate cca-to-legacy --write
```

The `@carbon/angular/legacy` components match the `carbon-components-angular`
API exactly. See the
**[Legacy carbon-components-angular](?path=/docs/legacy-carbon-components-angular-overview--docs)**
section of this Storybook for the full list of available adapters and their
usage examples.

### Step 2 — Incremental modernization to `@carbon/angular`

Once your application is running on `@carbon/angular/legacy`, migrate individual
components to `@carbon/angular` at your own pace. The modern entry point uses
the `@carbon/web-components` API directly — slot projection instead of `[items]`
arrays, flat `@Input()`s instead of model objects.

```ts
// Legacy
import { ButtonComponent } from '@carbon/angular/legacy';

// Modern
import { ButtonComponent } from '@carbon/angular';
```

Run the modernization codemod to handle import path changes:

```bash
npx @carbon/upgrade migrate cca-to-angular --write
```

Some components require manual template updates at this step — see
[Breaking changes](#breaking-changes) below for the full list.

---

## What stays the same across both steps

- **Selectors** — all `cds-*` selectors are preserved; your templates do not
  change between CCA and `@carbon/angular/legacy`, and do not change again when
  moving to `@carbon/angular`.
- **`[(ngModel)]` and `[formControl]`** — reactive and template-driven forms
  work identically via `ControlValueAccessor`.
- **SCSS imports** — all `@carbon/styles` import paths are unchanged.
- **`@carbon/web-components` v12** — both entry points are backed by the same
  Web Components, so you get full v12 design language, AI components, fluid form
  variants, and complete UI Shell from Step 1 onwards.

## Breaking changes

These apply when moving from `@carbon/angular/legacy` to `@carbon/angular` (Step
2). Step 1 has no breaking changes.

> Full detail (Before / After / Why / Migration steps) is in
> [`docs/guides/cca-to-angular.md`](https://github.com/carbon-design-system/carbon/blob/main/docs/guides/cca-to-angular.md).
> This page is the discoverable entry point; the guide is the authoritative
> reference.

### `TableModel` / `TableHeaderItem` / `TableItem` removed

The CCA model classes are replaced by plain object interfaces:

**Before:**

```ts
model = new TableModel();
model.header = [new TableHeaderItem({ data: 'Name' })];
model.data = [[new TableItem({ data: 'Alice' })]];
```

**After:**

```ts
columns = [{ header: 'Name' }];
rows = [{ cells: ['Alice'] }];
```

Run `npx @carbon/upgrade migrate cca-remove-table-model --write`.

---

### `notificationObj` removed — use flat `@Input()`s

**Before:**

```ts
notificationObj = {
  title: 'Error',
  subtitle: 'Something went wrong',
  type: 'error',
};
```

```html
<cds-notification [notificationObj]="notificationObj"></cds-notification>
```

**After:**

```html
<cds-notification
  title="Error"
  subtitle="Something went wrong"
  kind="error"></cds-notification>
```

Run `npx @carbon/upgrade migrate cca-remove-notification-obj --write`.

---

### `PaginationModel` removed — use flat `@Input()`s

**Before:**

```ts
paginationModel = new PaginationModel();
paginationModel.totalDataLength = 100;
paginationModel.pageLength = 10;
```

**After:**

```html
<cds-pagination [totalItems]="100" [pageSize]="10" [page]="1"></cds-pagination>
```

Run `npx @carbon/upgrade migrate cca-remove-pagination-model --write`.

---

### UI Shell: projected children replace array inputs

`[navigationItems]`, `[menuItems]`, and `[headerItems]` array inputs are
replaced with projected `<cds-header-item>` / `<cds-sidenav-item>` children.
This change cannot be automated — see the migration guide for step-by-step
instructions.

Run `npx @carbon/upgrade migrate cca-report-ui-shell-nav` to identify affected
files.

---

### `[theme]` input removed

The `[theme]` input has been removed from all components. Use CSS custom
properties via `@carbon/styles` to control theming globally.

Run `npx @carbon/upgrade migrate cca-remove-theme-input --write`.

---

### `appendInline`, `dropUp`, `scrollableContainer` removed

These positioning inputs have been removed. `@carbon/web-components` uses
Floating UI for automatic placement — no replacement is needed.

## Codemods reference

| Codemod                       | Type   | What it does                                                                      |
| ----------------------------- | ------ | --------------------------------------------------------------------------------- |
| `cca-report-imports`          | report | Lists all `carbon-components-angular` imports with equivalents                    |
| `cca-to-legacy`               | write  | Rewrites import paths to `@carbon/angular/legacy` (Step 1)                        |
| `cca-to-angular`              | write  | Rewrites import paths from `@carbon/angular/legacy` to `@carbon/angular` (Step 2) |
| `cca-remove-table-model`      | write  | Replaces `TableModel` with flat `[rows]` / `[columns]`                            |
| `cca-remove-notification-obj` | write  | Replaces `notificationObj` with flat inputs                                       |
| `cca-remove-pagination-model` | write  | Replaces `PaginationModel` with flat inputs                                       |
| `cca-remove-theme-input`      | write  | Removes `[theme]="theme"` bindings                                                |
| `cca-report-ui-shell-nav`     | report | Flags `[navigationItems]` / `[menuItems]` array bindings                          |

## Running both versions side by side

`@carbon/angular` registers each WC backing element under its real `cds-*` tag
(ADR 0015). Running both `@carbon/angular` and `carbon-components-angular` on
the same page is an **open question** — see
[ADR 0015](../../../docs/decisions/0015-angular-wrapper-host-is-the-web-component.md)
for the current status. The legacy entry point (`@carbon/angular/legacy`) is the
supported migration bridge and does not have this concern.
