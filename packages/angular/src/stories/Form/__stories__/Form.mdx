## Overview

The `Form` component is configurable to fit various use cases and layouts. It is
purposely simple out of the box, and users are responsible for configuring it to
suit their needs.

### Importing

```ts
import { FormComponent } from '@carbon/angular/form';
import { TextInputComponent } from '@carbon/angular/text-input';

@Component({
  standalone: true,
  imports: [FormComponent, TextInputComponent],
  template: `
    <cds-ng-form>
      <form aria-label="Sign up">
        <cds-ng-text-input
          name="email"
          label="Email"
          placeholder="you@example.com"></cds-ng-text-input>
      </form>
    </cds-ng-form>
  `,
})
export class MyComponent {}
```

## Accessibility Considerations

### Accessible Name

To comply with accessibility requirements, make sure to supply the component
with an accessible name by providing either the `aria-label`, `aria-labelledby`
or `title` attribute. Read more on the accessible naming rule
[here](https://able.ibm.com/rules/archives/latest/doc/en-US/aria_accessiblename_exists.html).

## Angular-specific notes

### Date picker

The classic date picker is not available in `@carbon/angular`. The form stories
use `cds-ng-preview-date-picker` from `@carbon/angular/date-picker` instead.

### Forms Integration

The form controls used inside `cds-ng-form` implement `ControlValueAccessor`, so
they work with `[(ngModel)]` and with `[formControl]` / `formControlName`. See
the `ReactiveForm` story (hidden from the sidebar and docs) for an example that
uses `ReactiveFormsModule` and `FormBuilder`.

### Form participation

For how the form controls take part in a native `<form>` (validation,
`FormData`, `requestSubmit()`), see
[Preview/Form participation](?path=/docs/preview-form-participation--docs).
