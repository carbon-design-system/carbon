# Changelog

### August 5, 2026

A new preview `DatePicker` has been added to `@carbon/react` as
`preview__DatePicker`. It is built on the
[Temporal API](https://tc39.es/proposal-temporal/docs/) and a framework-agnostic
state machine shared with `@carbon/web-components`, replacing the
Flatpickr-based implementation. Stories and documentation can be found in the
`Components/Preview/preview__DatePicker` section of Storybook.

The preview namespace exports `DatePicker`, `DatePickerInput`, and
`DatePickerSkeleton` under `preview__DatePicker`. Migrating is largely an import
change — see the
[migration guide](https://github.com/carbon-design-system/carbon/blob/main/packages/react/src/components/DatePicker/next/MIGRATION.md)
. Flatpickr-specific props on the v11 `DatePicker` (`appendTo`, `enable`,
`parseDate`, etc.) are now deprecated and will be removed in the next major
release.

We'd like feedback on
[github](https://github.com/carbon-design-system/carbon/issues/new/choose) or
any of the #carbon-\* channels on Slack on the following:

- API and prop surface
- Behavioral differences from the Flatpickr-backed component
- Accessibility concerns
- Any blockers, issues, etc.

### July 22, 2026

Initial motion API has been added to `@carbon/motion` and `@carbon/react`
packages. Stories along with documentation in the Overview page can be viewed in
the `Elements/Motion` section of Storybook. The initial work covers definition
of "surfaces" which are different motion animations we want to standardize
(currently examples!) and new React wrapper components that implement the
[Motion library](https://motion.dev/) under the hood. There is an option to also
utilize native CSS for the "reveal" surfaces.

In terms of accessibility, if use-prefer-reduced-motion is detected, the motion
API will fallback to the current behavior in Carbon motion. Exploration of
motion accessibility was done and captured in
[issue #22686](https://github.com/carbon-design-system/carbon/issues/22686).

We'd like feedback in #carbon-collective channel on Slack on the following:

- Design concerns
- Accessibility concerns
- Developer ergonomics/api
