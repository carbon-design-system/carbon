OKLCH Spike — Visual Demo

packages/themes · Phase 1–3 · GitHub #22660 · Data from color-palette.json

What you're looking at: Carbon's 9 background color tokens, each shown in two formats side by side — hex (what browsers get today, e.g. #0f62fe) and oklch() (a smarter description of the exact same color, e.g. oklch(0.557 0.243 262)).

The point of every section below is the same: these two formats describe identical colors. The conversion is lossless. Nothing shipped to users changes.
Checking your browser…
Section 1 — The 9 background tokens, hex vs oklch()
Each card is one background token. The color swatch is split down the middle — left half painted with hex (today's format), right half painted with oklch() (future format). They should look pixel-identical — because they describe the same color. The thin vertical line in the middle is the divider between the two halves.

Below the swatch: the token name, which design role it plays, and all its numbers. L = lightness (0–1), C = chroma/vividness (0 = grey), H = hue angle (degrees on a color wheel).
Section 2 — Are they really the same? The proof strip
All 9 tokens shown side by side. Top half of each column = hex. Bottom half = oklch(). Hover over any column to see the token name.
Look for any visible seam or colour difference between the top and bottom halves. There should be none — if the conversion is lossless, both halves are identical.
Top half = hex (today) Bottom half = oklch() (future)
Section 3 — Lightness (L) at a glance
This is what OKLCH unlocks that hex never could. Each bar shows how perceptually light a token is — 0 = pure black, 1 = pure white. The bar length is the L value. The bar is filled with the actual token color.

Notice: all the greys are spread evenly across the scale. Blue 60 sits in the middle — it's medium-light, which is why it works as an accessible brand color on white backgrounds. You could never read this information from a hex code.
Section 4 — Why OKLCH matters for transitions and motion
Both gradients below go from white → IBM blue. The only difference is the color space used to calculate the in-between colors.

sRGB (the old way, used by hex colors) produces a washed-out grey in the middle. OKLCH stays vivid all the way through. This is what a theme-switch animation looks like in each space — and why OKLCH matters for v12 motion work.

Both gradients are rendered live by your browser right now — no images.
